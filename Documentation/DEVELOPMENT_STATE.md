## DONE (local, not pushed): productive taskwork + policy RNG (`490a742`)
`RuleBrain._extract_features` now emits `productive_taskwork_available` (1.0/0.0), derived only from observed `built_state`, `site_capacity_summary`/bridge-unlock state and the LEGAL AFFORDANCES (presence = legal; the `reachable` flag is NOT legality: it only says a straight path exists now and is false for start affordances at spawn, which caused an early false negative that was fixed). TRUE when any of: a brick source or carried brick (the transport affordance is legal only then) and an unfinished project or bridge needing material; a bridge ready to build; an already-resourced project that can continue; a fully built or validation-ready project awaiting validation (readiness may still need knowledge); a project needing repair with repair legal; a startable structure with a brick source and remaining buildable capacity. FALSE otherwise (stranded unfinished structures, no source).
When FALSE the Procedural Baseline: zeroes `coordination_deadlock_pressure` and `no_active_plan_pressure` (coordination cannot create bricks); boosts MONITOR and demotes COORDINATE/INTEGRATE_DIK/LOGISTICS/CONSTRUCT/REPAIR/VALIDATE; boosts WAIT and demotes consult/externalize/communicate/request-assistance/start/transport; stops forcing a concrete action over REASSESS/OBSERVE and the meta-streak override; treats the state as an emergency method switch so a committed method does not hold it to stranded work. Middleware does not force idling. When work reappears the feature returns to 1.0 and normal behaviour resumes (unit-tested).
POLICY RNG DEFECT: the rng key was `{policy_seed_key}-{n_affordances}-{mode}-{goal_pressure}` with no time component, so in an unchanged state every tick replayed one draw; an agent whose draw fell in a tail (e.g. 9% mass on `repair_or_correct_construction` while WAIT had 0.91) repeated that action indefinitely (137-237 selections observed on seed 1). Fix: the key now also contains `control_state["sim_step"]` (int simulation time). It stays a pure function of run seed (`ctx:{run_seed}:{agent_id}`), agent, step and decision context; no wall clock or process entropy (string-seeded `random.Random` is deterministic). Consequence: exact stochastic trajectories differ from every commit before `490a742`; do not compare action sequences across that boundary.
Verified: same seed twice (seed 2, 500 s) gives an identical Pilot-selection sequence hash (75edffd0c0a282c0, 275 selections) and identical construction outcome (12 complete/validated, 96 bricks delivered, piles 10/74, bridge_bc complete); a different seed (3) gives a different hash (366231d3d320fc96) and outcome; for a fixed key family the draw at 10 successive steps was 10 distinct values (the old key gave one value) and identical keys reproduce identical draws. Not verified in this session: >2 seeds for different-seed divergence; reproducibility over the full 2000 s horizon.
Tests: `tests/test_productive_taskwork_available.py` (12) + `tests/test_baseline_start_and_build_pressure.py`, `tests/test_pile_pickup_accounting.py`, `tests/test_mission_timing_semantics.py`: 28 passed together.

A house is fully supported only with effective food (a food link to a WATERED greenhouse) and effective water.
